## Harness findings and prior failures

1. A new executable path can re-open file-association setup despite an initialized source host. The owned handler declines only the exact known prompt and acknowledges its specific follow-up notice. It never registers associations. This route is bounded by the public Lab [PR 155 launcher](https://github.com/ziro-lab/chat-native-work-lab-001/blob/4d6a92a1ad3c7e9b9845317057d2b3a064f2217f/experiments/ymm4/tachie-paused-completion/RunNative.ps1).
2. On this Save provider, UIA `ValuePattern.SetValue` plus matching readback, even with verified focus, did not update the filename actually submitted. The dialog still proposed the old default target. The test rejected that overwrite. The filename control was uniquely resolved beneath `FileNameControlHost`; the owned native Edit accepted documented [EM_SETSEL](https://learn.microsoft.com/en-us/windows/win32/controls/em-setsel)/[EM_REPLACESEL](https://learn.microsoft.com/en-us/windows/win32/controls/em-replacesel) messages, and later media existed at the exact owned path. This is a measured provider-specific workaround, not a general UIA claim.
3. `EncodeFrom=0, EncodeTo=4` produced callbacks 0–3 and four decoded frames. `EncodeTo=5` produced callbacks 0–4 and five decoded frames. The earlier expected-five assertion confused this observed exclusive endpoint. Other range modes remain unproved.
4. The normal writer did not trigger the main view model's Save-request observer used by the old harness. Accepted output is checked through the actual owned media and decode, rather than treating that observer as a writer contract.
5. A terminal progress token was canceled even in a successful cold output where Cancel was never invoked. Token state alone cannot distinguish cancellation from completion. Record actual command invocation, user flag, callbacks and media.
6. Output exceptions appeared in WPF `FeedbackViewModel`, not the expected standard `#32770` dialog. The updated timer requires the owned window/type, output-failure text, synthetic item label and a correlated Source error, records visible text, and closes the window through public WPF. It does not send feedback.
7. Early trials stopped before export, at harness assertions, or on an unhandled feedback window. They remain preserved FAIL/BLOCKED records. One later trial cleared the shared input copy before a subsequent case; running reference-clear last prevents that test-order contamination. None is silently converted into product PASS.
